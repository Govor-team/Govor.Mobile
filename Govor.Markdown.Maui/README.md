# Govor.Markdown

Нативный Markdown для сообщений и описаний профиля в .NET MAUI 10.

## Проекты

- `Govor.Markdown`: Markdig → неизменяемый план отображения, без зависимости от MAUI.
- `Govor.Markdown.Maui`: `MarkdownView`, использующий этот план.
- `Govor.Markdown.Tests`: тесты формата, ограничений, URL и многопоточного LRU.
- `Govor.Markdown.Benchmarks`: воспроизводимый микрозамер разбора и кэша.

Все проекты находятся рядом с `Govor.Mobile`, добавлены в решение. Библиотека не зависит от приложения или UIKit; её можно перенести в другое решение с ядром.

## Подключение

Добавьте ProjectReference на `Govor.Markdown.Maui.csproj`. Регистрация обработчиков в MauiProgram не нужна.

```xml
xmlns:md="clr-namespace:Govor.Markdown.Maui;assembly=Govor.Markdown.Maui"

<md:MarkdownView MarkdownText="{Binding Text}"
                 FontSize="14"
                 TextColor="#F5F0FF"
                 HeadingColor="#6B50ED"
                 HyperlinkColor="#6394B7"
                 CodeBackgroundColor="#353b4d"
                 ImageHeight="100"
                 BlockSpacing="6"
                 LoadImages="True"
                 OnHyperLinkClicked="OpenLink" />
```

```csharp
private void OpenLink(object sender, Govor.Markdown.Maui.LinkEventArgs e)
{
    e.Handled = true;
    // Передать e.Url своему роутеру / команде открытия браузера.
}
```

Без `Handled = true` контрол открывает ссылку через `Launcher.Default`. Событие `LinkOpenFailed` сообщает об ошибке открытия. `RenderFailed` сообщает об ошибке фонового разбора; в таком случае остаётся исходный текст. Все свойства оформления — BindableProperty; изменение темы перестраивает представление по готовому плану без повторного разбора.

## Поддерживаемый формат

- Заголовки H1–H6, включая Setext, абзацы и переносы строк.
- `**жирный**`, `*курсив*`, вложенные выделения, `~~зачёркнутый~~`, `==подсвеченный==`.
- Ссылки, reference links, URL без разметки, email.
- `![описание](https://host/image.png)`, изображения-ссылки; изображения выводятся отдельным блоком с сохранением порядка текста.
- Маркированные, нумерованные и вложенные списки (компактные текстовые маркеры).
- Цитаты, разделители, inline code, fenced / indented code.

HTML выводится как текст. Таблицы, LaTeX, SVG-рендерер, task-checkbox UI, подсветка синтаксиса, атрибуты размера изображений и другие расширения Indiko не реализованы. Исходный текст неподдерживаемых расширений обычно остаётся обычным текстом. Вложенность списков показывается составным префиксом; сложная типографика документов не является целью этого контрола.

Выделение здесь означает форматирование и подсветку. Выбор произвольного диапазона текста системными маркерами и копирование диапазона не реализованы: это требует отдельных платформенных обработчиков вместо стандартного MAUI Label.

Ссылки разрешены только HTTP, HTTPS, mailto; изображения — HTTP/HTTPS. Относительные пути, file/data/javascript URL не открываются. Для SVG и других форматов действует поддержка стандартного MAUI Image на целевой платформе. Битая картинка сохраняет зарезервированное место и семантическое описание; отдельный UI ошибки загрузки не реализован. `LoadImages=False` показывает alt-текст без сетевой загрузки. URI-изображения используют стандартное дисковое кэширование MAUI на 7 дней.

## Почему это подходит для ленты

Обычное сообщение — один Label непосредственно в ContentView, без вложенного StackLayout. Для форматирования используются Span, а не отдельные Label. Для документа из нескольких блоков создаётся один VerticalStackLayout и один нативный элемент на блок. Обычный текст без выделений использует Label.Text без FormattedString.

Глобальный LRU хранит только неизменяемые планы, максимум 256 записей и 1 048 576 символов исходного текста. Контролы, жесты и BindingContext не попадают в кэш. Очень большие исходники не кэшируются. Для очистки в интеграции предусмотрен `MarkdownCache.Shared.Clear()`; автоматической привязки к аккаунтам в библиотеке нет.

Первый разбор текста длиннее 512 символов выполняется вне UI-потока, одновременно работают не более двух задач разбора. Пока он идёт, виден ограниченный исходный текст. Это может один раз изменить высоту после применения форматирования; при попадании в кэш промежуточного текста нет. Короткие сообщения разбираются синхронно. При смене BindingContext через привязку MarkdownText или выгрузке контрола старый результат не может заменить новое сообщение: используются отмена и номер запроса. Выгрузка освобождает дерево и план; повторный показ использует кэш.

Размер изображения резервируется через ImageHeight до загрузки: получение размеров файла не меняет высоту строки. Это уменьшает скачки при загрузке. Контрол не содержит ScrollView; прокруткой и виртуализацией управляет внешний CollectionView.

Вход ограничен 32 768 UTF-16 символами, 256 блоками и 2048 обрабатываемыми фрагментами. При усечении выводится многоточие. Это сознательные ограничения для пользовательского контента в ленте, а не полноразмерного просмотрщика книг.

## Проверка

```powershell
dotnet test Govor.Markdown.Tests/Govor.Markdown.Tests.csproj
dotnet build Govor.Markdown.Maui/Govor.Markdown.Maui.csproj -f net10.0-android
dotnet build Govor.Markdown.Maui/Govor.Markdown.Maui.csproj -f net10.0-windows10.0.19041.0
dotnet run --project Govor.Markdown.Benchmarks -c Release
```

Микрозамер на текущей машине (Release, 5000 повторов, 24.10.2026):

| Исходник | Разбор, мкс/операция | Кэш, мкс/операция | Разбор, байт/операция | Кэш, байт/операция |
|---|---:|---:|---:|---:|
| 20 символов | 4.634 | 0.777 | 904 | 0 |
| 47 символов | 17.302 | 0.083 | 3144 | 0 |
| 83 символа | 34.802 | 0.118 | 4816 | 0 |
| 2800 символов | 148.726 | 0.681 | 152800 | 0 |

Это ориентировочный Stopwatch-замер ядра; JIT и порядок прогрева влияют на результаты. Создание native view, layout, декодирование изображений и FPS сюда не входят. Сравнение скорости прокрутки с Indiko на устройстве пока не выполнено. Сборка на Windows также не подтверждает работоспособность iOS/MacCatalyst на устройствах.

Для проверки прокрутки на Android следует сравнить Release-сборки до/после на одном устройстве с одинаковой историей: короткие сообщения, смешанная разметка, длинные документы и изображения. Проверять холодный и повторный проход, быстрые развороты прокрутки, изменение текста и темы, переходы со страницы и обратно, попадание по ссылкам после переиспользования ячеек. В Perfetto / Android Studio Profiler сравнить пропущенные кадры, время UI-потока, GC и память. Не использовать ItemSizingStrategy=MeasureFirstItem для сообщений разной высоты. Единственное изменение рендерера не исключает задержек в остальной разметке пузыря и обработчиках прокрутки.

## Другие варианты

- [Plugin.Maui.MarkdownView](https://github.com/Toine-db/Plugin.Maui.MarkdownView): готовая бесплатная библиотека, MIT, нативный MAUI UI. Стоит проверить на той же истории; подтверждения, что она быстрее Indiko в этом чате, нет.
- [Markdig](https://github.com/xoofx/markdig): бесплатный парсер BSD-2-Clause, используется ядром. Сам по себе не рисует интерфейс.
- Собственные платформенные TextView / UITextView / RichTextBlock: перспективный следующий шаг, если профилирование покажет, что основное время остаётся в MAUI Label/Span. Можно разместить несколько стилей абзацев в одном нативном текстовом контейнере и добавить системное выделение текста, но потребуется отдельный рендерер на каждой платформе.
- SkiaSharp / GraphicsView: можно уменьшить число native view, однако переносы, hit testing ссылок, accessibility, Unicode/bidi и выделение диапазонов придётся реализовать и поддерживать отдельно.
- HTML в WebView имеет смысл для отдельных длинных документов; по WebView на сообщение добавит тяжёлые элементы в виртуализируемый список.

Формат хранения сообщений менять не требуется. В Govor новый контрол подключён во всех трёх прежних местах использования Indiko, старые registration и PackageReference удалены.
